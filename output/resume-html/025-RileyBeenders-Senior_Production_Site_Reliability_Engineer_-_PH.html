ExtrusionStudio | Plant measurement and production system, Proteor
September 2025 - Present

Python, asyncio, Modbus TCP, Starlette, SQLite, Server-Sent Events, Raspberry Pi, Debian

Problem: Each of three extrusion lines had a tri-axial laser gauge, and the only record of a spool's diameter was whatever an operator wrote down. Production was speeding up, and the plant needed every reading captured, every spool judged against its tolerance, and the result visible on the floor at once.

  • Runs one asyncio poller and Modbus TCP session per line, reading every line concurrently at 20 Hz so a powered-down line never stalls a healthy one; the poll rate is per-line configuration with a floor, because the right value depends on the PLC's response time.
  • Built for supportability: Server-Sent Events that reconnect by themselves, no internet dependency on the floor, guides served by the server itself, a hand-written Modbus simulator that shares no code with the client, and a server that updates itself daily from its checked-out git branch so a fix can be tried on the real system.
  • Added a calibration phase that times the filament from the laser to the spool, a delay of one to two minutes through the accumulator, so each reading and alarm lands on the spool it is actually wound on instead of firing at the laser.
  • Logs every spool to its own CSV and a SQLite run table with a serial, QR label, and HTML certificate; print-on-demand thermal labels replaced full-sheet printing, removing up to about 30% of label waste per run.
  • Runs a fleet of Raspberry Pi kiosks (projector, a touch screen per line, packing bench, statistics TV) that check in with the server and are updated, configured, and switched on and off with the work hours from one settings panel.
