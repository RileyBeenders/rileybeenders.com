ExtrusionStudio | Plant-wide measurement and production system, Proteor Printing Solutions
September 2025 - Present

Python, asyncio, Modbus TCP, Starlette, SQLite, Server-Sent Events, Raspberry Pi, Debian, LabVIEW, thermal label printing

  • Problem: three extrusion lines each had a tri-axial laser gauge, but a spool's diameter was recorded only by hand; as production sped up, the plant needed every reading captured, judged against tolerance, and visible to operators, the packing bench, and management at once.
  • Proved the Modbus TCP communication and register decoding with a LabVIEW proof of concept, then rebuilt the program from scratch in Python as one service: one asyncio poller and one Modbus session per line, a hub that keeps the ring buffer and statistics, and Server-Sent Events to every browser. It reads every line concurrently at 20 Hz, so a powered-down line never stalls the others. The poll rate is set per line because the right value depends on the PLC's response time.
  • Gave each audience its own panel in its own process, with only Admin Settings allowed to talk to the gauges: live strip charts with tolerance-band alarms and out-of-spec timers for operators, an approve / inspect / reject workflow with spool, box, and master case labels on a thermal printer for the packing bench, and a statistics view for management. Each frame carries min, max, and last per channel, so a spike between frames still shows on the chart.
  • Added a calibration phase that times the filament from the laser to the spool and delays logging by that offset, so every reading is tied to the spool it is physically wound on. Each spool is logged to its own CSV and a SQLite run table and gets a serial, a QR label, and an HTML certificate on approval, so the packing bench decides spools against the gauge's figures instead of by eye.
  • Deployed Raspberry Pi kiosks (projector, a touch screen per line, packing bench, statistics TV) on a floor with no internet, served by a headless Debian server. They boot straight to their page, check in every 30 seconds, and are updated, configured, and switched on and off with the work hours from one settings panel. A hand-written Modbus simulator that shares no code with the client keeps a test from hiding the same bug twice.
