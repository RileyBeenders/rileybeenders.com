The site as its own case study: how it was designed, the agents that maintain it, and how far it has come in a short time.

01  The site

The site you are reading. A resume-shaped evidence layer built from scratch, then handed a set of AI agent skills that tailor resumes, keep its documentation honest, and now carry its motion language. It started on June 28, 2026 and has not stopped moving.

  • Designed the Blueprint Press system: paper, ink, hairline rules, a fixed blueprint grid, and one easing curve shared by every transition, with ten palettes and a dark mode switchable from a local Studio.
  • Built a library of repository agent skills that generate job-targeted resume PDFs, keep an Obsidian vault in sync with the code, and distill a motion vocabulary from svelte-bits into this site's own restrained style.
  • Went from a single resume JSON to a data-driven Next.js site with a content editor, analytics, a social card, and a job-application tracker, deploying continuously the whole way.

What it's made of

Blueprint Press

The site is set on paper with ink, one accent, and hairline rules, over a fixed blueprint grid you can see through the page. Which colors those are is not fixed in the code: paper, ink, and accent are CSS tokens, filled from whichever palette is chosen in the Studio's Site Settings, so the page re-inks itself from a form. Headings are Instrument Serif, body is Spectral, and every transition on the site uses one easing curve so the motion reads as a single hand.

Skills in the repository

Standing instructions for any AI coding agent live in .agents/ as plain markdown, one folder per procedure, routed by a README. custom-resume builds a job-targeted PDF from a posting and the site's data. vault-sync keeps an Obsidian vault of 35 notes matching the code in the same session as any change. sync-charts keeps the application tracker identical in two places.

A resume that shows its work

The PDF stays the official application document. The site is the evidence layer behind it: each line of the resume links to a project, and each project opens into the problem, the approach, and what changed.

    One posting in, one page out

    The PDF is still the document that gets submitted. When I apply somewhere, an agent reads the posting, pulls the matching evidence out of the same data this site renders, and writes a one-page PDF in the site's format. Anything the data can't back up is left out, not softened.

    The Download PDF button on the home page serves my main resume, printed in the same format. A second agent keeps it current: it reads what changed in the data since the last build, asks me which findings belong on the page, and reprints it.

    Edit the site from a form, not a code editor

    Every word, image, palette, and font on this site comes from JSON files. The Studio is a small local editor that reads and writes them through a form built from a schema, so a content change never means opening a code file.

    It only runs on this machine, backs up every save, and writes back byte-for-byte what it read plus the one thing that changed, so the git diff is just that change.

    • Ten palettes plus custom colors, three font roles
    • Hidden projects keep their write-up until they publish
    • Never deployed: it is not part of the site

    Standing instructions any agent can follow

    The repository carries its own instructions for AI coding agents, written as plain markdown so any tool can follow them. Each one is a procedure I would otherwise have to remember: how to tailor a resume, how to keep the documentation honest, how motion on this site should feel.

    They are the reason a fresh session can pick up work cold and still do it the way I would.

    • Plain markdown in the repo, one folder per procedure
    • Registered as first-class skills so they trigger on ordinary requests
    • A vault of notes is kept current in the same session as any change
